# 踩地雷 Minesweeper（WinXP 原味復刻 + 無猜盤面）

Vite + React + TypeScript 的踩地雷 PWA。桌機滑鼠三鍵全支援、手機長按插旗，可安裝到主畫面、離線可玩。

## 特色

### WinXP 原味

完全照 `winmine.exe` 的行為做，不是「長得像」而已：

- **三難度**：初級 9×9/10 雷、中級 16×16/40 雷、高級 **30 寬 × 16 高**/99 雷（很多仿作抄成 16×30），另有自訂盤（最大 30×24）
- **和弦展開**：左右鍵同按（或中鍵）——數字周圍的旗數剛好等於數字時，一次翻開其餘鄰格。**旗插錯了會炸**，這是它的代價，不幫玩家擋
- **問號標記**：右鍵循環 旗 → ? → 空白，可在「遊戲 → 標記(?)」關掉
- **笑臉鈕**：🙂 常態 / 😮 按著 / 😎 通關 / 😵 踩雷
- **七段顯示器**：黑底紅字，左邊剩餘雷數（可以是負數）、右邊計時器（上限 999，第一次點擊才起跑）
- **數字配色**：1 藍 2 綠 3 紅 4 深藍 5 褐 6 青 7 黑 8 灰，一個都沒換
- **踩雷畫面**：踩到的那顆紅底、其餘雷全掀、插錯的旗畫紅叉
- **通關**：非雷格全開後自動把剩下的雷插旗、剩餘雷數歸零
- 圖示全部是 SVG 手繪，**不用 emoji**——地雷和旗子長什麼樣是這款的招牌，不能交給平台字型決定

### 無猜盤面（可關）

經典踩地雷會出現只能賭運氣的 50/50。打開「無猜盤面」之後：

1. 玩家按下第一格
2. 隨機佈雷（避開首點）
3. 讓推理引擎從首點自己玩一遍
4. 全開得了就採用，卡住就丟掉重抽

盤面是在**第一格按下去之後**才生成的，所以生成器知道玩家從哪裡開始，能一直重抽到抽出一盤保證不用猜的為止。

推理引擎（`src/game/solver.ts`）三層，由便宜到昂貴：

| 層 | 規則 |
|---|---|
| ① 單格規則 | 數字周圍已知雷數滿了 ⇒ 其餘鄰格安全；數字等於未開鄰格數 ⇒ 全是雷 |
| ② 子集規則 | A=1 管 {a,b}、B=2 管 {a,b,c}，雷數差 1 而多出來的只有 c ⇒ c 必是雷（1-2-1 直覺） |
| ③ 窮舉 + 全域雷數 | 把邊界連通塊的所有合法擺法列出來，再用剩餘雷數做跨塊的可行性 DP；某格在每一種可行擺法裡都一樣 ⇒ 確定 |

**鐵則：只能少推，絕不能推錯。** 第 ③ 層有節點上限，超限就放棄那個連通塊——放棄時把它的雷數範圍放寬成超集，讓全域推論仍然成立。寧可生不出無猜盤，也不可以生出「宣稱無猜、其實要賭」的盤。

實測生成成本（`npm run bench`）：

| 難度 | 首點規則 | 成功率 | 平均 | 最慢 |
|---|---|---|---|---|
| 初級 9×9/10 | 保證開一片 | 25/25 | 1ms / 1 次抽 | 4ms |
| 中級 16×16/40 | 保證開一片 | 25/25 | 2ms / 1 次抽 | 8ms |
| 高級 30×16/99 | 保證開一片 | 25/25 | 63ms / 8 次抽 | 320ms |
| 高級 30×16/99 | XP 原味 | 25/25 | 61ms / 29 次抽 | 294ms |

預算 2500ms 內生不出來時，**退回一般盤面並在狀態列誠實標成「⚠ 一般盤面：可能需要猜」**。

### 首點保護（兩種，可選）

- **現代友善**（預設）：保證首點是零格，一點展開一整片。Win7 之後的官方版與手機 App 都這樣
- **XP 原味**：只保證首點不是雷，可能一點就開出一個「5」

### 教練層:提示 / 悔一步 / 死因分析 / 教學回放

這四件事共用**同一支推理引擎**(`src/game/solver.ts` → `src/game/coach.ts`)——
也就是當初拿來保證「這盤不用猜」的那一支。示範跟保證是同一件事,不會教的跟做的不一樣。

- **💡 提示(H)**:指一格「一定安全」(綠)或「一定是雷」(紅),並說出是用哪一條規則看出來的
- **↩ 悔一步(U)**:一局 3 次;**踩到雷也能復活**
- **💥 死因分析**:踩雷當下用**踩下去之前**那一份盤面問引擎三個問題 ——
  ①這顆當時推得出來是雷嗎 ②當時有沒有別的「一定安全」的格子 ③還是真的只能猜?
  第三種會**明講「不是你的錯」**:把運氣講成技術問題,孩子只會覺得自己笨
- **🤖 教學回放**:一局結束後把整盤從第一格重推一遍,一步一步演;推不動時誠實說「這盤到這裡就要猜了」

★ **鐵則:提示只能少講,絕不能講錯。** 所以教練層**刻意不讀玩家插的旗** ——
旗子可能插錯,把錯的「已知雷」餵進去,推出來的「一定安全」就是假的,而孩子會照著點下去。
測試用 200 個隨機盤逐格驗過:提示說安全的一定不是雷、說是雷的一定是雷。

★ **用過提示或悔一步的那一局不計入最佳成績** —— 不然最佳時間表會被輔助功能灌爆,
正常玩的紀錄永遠破不了(同一條教訓:無猜盤與一般盤也是分開記的)。

### 鍵盤(不用滑鼠也能玩)

方向鍵/WASD 移動、**空白或 Enter** 翻開(站在數字上就是和弦)、**F** 插旗、
**H** 提示、**U** 悔一步、**Esc** 收提示、**F2** 新局。
整張棋盤只有一個 tab 停留點(`aria-activedescendant` 指出游標在哪格)——
480 格各給一個 tabIndex 的話,使用者要按 480 次 Tab 才離得開棋盤。

### 換皮 7 種 / 換背景 8 種 / 背景音樂 3 首

三個旋鈕各選各的(想要經典灰棋盤配星空、或高對比棋盤配素色底,都行):

- **主題**換的是視窗面、斜角、標題列、七段顯示器與**數字八色**。深色皮一定要整組換掉八色 —— 只換底色的話,深色上的藍色「1」會直接消失。每個主題逐色算 WCAG 對比,有測試守著
- **背景**是視窗後面那片「窗外風景」,全部是**現畫的向量場景**(零圖檔、離線一樣看得到):

  | 背景 | 畫了什麼 |
  |---|---|
  | 草原藍天 | 太陽(光暈+八道光芒)、三朵白雲、七道彩虹、樹林(闊葉/松/灌木)、野花與草叢、飛鳥 |
  | 星空夜色 | 弦月(mask 挖的)、兩層星空+四角星、流星、銀河薄霧、兩道遠山稜線 |
  | 月夜森林 | 滿月與環形山、星空、針葉林剪影、螢火蟲 |
  | 夕陽 | 落日與霞光、暖色晚霞兩朵、歸鳥、山稜剪影 |
  | 98 青綠 | 當年那種 8×8 點陣圖樣 + 暗角 |
  | 素灰 | **刻意保持乾淨**:只有極輕顆粒,投影上課用這張最不搶戲 |
  | 牛皮紙 | 紙纖維、斑點、兩處淡茶漬 |

  ★ 位置一律用百分比、大小一律用 `vmin` —— 手機直向和教室投影差四倍,寫死 px 的太陽在手機上會佔掉半個天空。
  ★ 景物刻意避開畫面正中央(遊戲視窗坐在那裡);夕陽的太陽就是這樣從正中移到左側的。
- **背景音樂**和音效分開(有人要音效不要音樂),三首原創、即時合成、無音檔,**預設關**——別人家的孩子在圖書館打開不該突然出聲

### 其他

- **每日挑戰**：`?daily` 是今天的題，`?seed=123456` 指定題號。因為踩地雷的盤面由「第一格點哪裡」決定，每日挑戰把**第一格也交給種子**，開局直接幫你點掉——全世界同一天拿到同一盤、同一個開場
- **個人紀錄**：三難度各自記最佳時間、勝率、最佳 3BV/秒。**無猜盤與一般盤分開記**（無猜明顯好過，混在一起的話一般盤的紀錄永遠破不了）
- **3BV 與效率**：3BV = 這一盤最少要點幾下；效率 = 3BV ÷ 實際左鍵次數（只在結算時顯示）
- **手機**：點一下開格、長按插旗（會震一下）、在數字上點一下和弦展開，另有 🚩 旗子模式把兩者對調
- **PWA**：可安裝、離線可玩
- **統計打點**:零個資(無 cookie、無 IP 存檔、無帳號),五個鍵構成一條漏斗 ——
  `minesweeper` 開頁 → `-start` **真的開局** → `-done` 通關(帶秒數)/ `-lost-done` 踩雷(帶存活秒數)/ `-quit-done` 中途放棄(帶存活秒數),外加 `-dwell` 真實停留。
  ⇒ **放棄率 = quit ÷ start**,平均存活秒數各自有 t 平均;
  「直接關分頁走人」的那群 = start −(done+lost+quit)的**殘差**。
  ★ 關分頁那種刻意不另外送一發:`-dwell` 就在 pagehide 送,而**手機鎖屏常常只送得出第一個 beacon** —— 同一刻連發兩發會掉一發。與其兩個數字都不可信,不如讓它當殘差算出來

## 開發

```bash
npm install
npm run dev        # 開發模式
npm test           # 單元測試（引擎 + 推理引擎 + 生成器，41 項）
npm run build      # 產出 dist/
npm run preview    # 本機預覽 dist（port 4173）
npm run verify     # 真瀏覽器行為驗收（需要 preview 先起來）
npm run bench      # 無猜盤面生成成本實測
```

⚠ **建置前一定會先清掉 `dist/`**(`prebuild` 自動做)。原因不是潔癖:
**Node 24 的 `fs.rm*` 只要「要刪的那條路徑含非 ASCII 字元」就會讓整個 node 進程硬當掉**
(Windows 退出碼 `0xC0000409`,沒有例外、沒有訊息),而 vite 的 `emptyOutDir` 正是用它。
這個 repo 目前住在含中文的路徑下 ⇒ 只要 `dist/` 存在,`vite build` 就停在
「✓ modules transformed.」然後無聲死掉,看起來像卡住。實測與對照組寫在
`scripts/clean-dist.mjs` 檔頭。**根治是把 repo 搬到不含中文的路徑。**

真瀏覽器驗收也可以打線上：

```bash
BASE=https://hfpc-minesweeper.summer09201017.workers.dev npm run verify
SHOT_DIR=scripts/out/shots npm run verify      # 順便存截圖
```

## 為什麼兩套測試都要

- **單元測試**證明「規則對」——和弦判定、零格連鎖、首點保護、推理引擎健全性（跑 300 個隨機盤，推出來的每一格都對照真實盤面驗一次）
- **真瀏覽器驗收**證明「畫面上做得到」——測試全綠但一開頁就被遮罩蓋住、按鈕被固定徽章偷走觸控，這兩種錯只有真的去點才看得到

## 部署

```bash
npm run deploy     # build + wrangler deploy --name hfpc-minesweeper --assets dist
```

⚠ 在含中文的路徑下,`npm run deploy` **部署成功但退出碼會是 `0xC0000409`**
(wrangler 收尾時去刪暫存目錄,踩到上面那個 Node 24 的 `fs.rm` 雷)。
判斷成不成功要看輸出裡有沒有 `Deployed hfpc-minesweeper triggers` 與網址,不要看退出碼 ——
否則 CI/腳本會把一次成功的部署當成失敗,然後有人去「修」一個沒有壞的東西。
