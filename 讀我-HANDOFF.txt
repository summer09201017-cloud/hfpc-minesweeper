■ 本機地雷(⚠⚠ 最重要的一條,不知道會查一整個下午)
------------------------------------------------------------
**Node 24 的 fs.rm* 只要「要刪的那條路徑含非 ASCII 字元」就會硬殺整個 node 進程**
(Windows 退出碼 0xC0000409 / -1073740791,沒有例外、沒有堆疊、沒有任何訊息)。

這個 repo 目前住在 C:\Users\agape250\Downloads\0916早\0916早\Desktop\hfpc-minesweeper
—— 路徑裡有「早」⇒

  · vite build 的 emptyOutDir 內部就是 fs.rm ⇒ **只要 dist/ 還在就必炸**,
    畫面停在「✓ 67 modules transformed.」然後無聲死,**看起來像卡住不像壞掉**。
    → 已用 scripts/clean-dist.mjs 當 prebuild 繞開(readdir+unlink+rmdir 自己遞迴)。
  · wrangler deploy 收尾刪暫存目錄也會踩到 ⇒ **部署成功但退出碼非 0**。
    → **判斷成敗看輸出有沒有「Deployed … triggers」與網址,不要看退出碼。**

  實測對照(同一台機、node v24.13.0;判準是**解出來的目標路徑**,不是工作目錄):
    目標純 ASCII                              → 正常
    目標是含中文的絕對路徑(工作目錄純 ASCII)→ 當掉
    工作目錄含中文 + 相對目標                 → 當掉(連刪單一檔案都當)
    同樣路徑改用 unlinkSync + rmdirSync       → 都正常

  ⇒ **根治:把 repo clone 到不含中文的路徑**(東西全部已 push,重 clone 一分鐘、零風險):
      git clone https://github.com/summer09201017-cloud/hfpc-minesweeper.git C:\Users\<你>\code\hfpc-minesweeper
  ⇒ 細節與 30 秒對照組定位法見合輯 skill `nonascii-path-trap`。

其他小地雷:
  · 主控台是 cp950 ⇒ python 腳本 print 中文會炸,加 PYTHONIOENCODING=utf-8。
  · 改 .md 給使用者看時,合輯的 hook 會自動附 .txt/.html(本 repo 的 README 就是三份)。
